# 风机历史数据包概览

## 数据来源

本数据包由以下两个历史资料批次整理，不新增原文件中不存在的工程结论：

1. “风机技术清标历史资料批次”：91 份可用历史清标资料。
2. “风机技术协议历史资料批次”：103 份可用历史技术协议。
3. 合计 194 份源文件，覆盖 XLSX、PDF、DOC、DOCX。
4. 业务使用边界来自《技术评标业务知识总结.docx》；该文件不是历史参数来源。

Skill 已内置结构化参数、案例索引、可检索原文语料、来源清单和检索脚本，可独立完成历史参数检索与对比。`source_batch` 只记录历史资料的构建批次名称，用于说明数据来源，不是运行路径，也不要求用户另行上传或打开外部文件。

原始 ZIP 本体不属于运行依赖。若某来源仅有图片、签章或无文本层内容，而包内没有可引用文本，自动分析必须排除该来源并写明“包内无可用文本证据，未纳入本次历史分析”；只有将后续 OCR 或人工确认结果正式补入 Skill 后，才可用于自动分析。

## 当前整理规模

- 源文件：194 份，其中清标资料 91 份、技术协议 103 份。
- 全文证据记录：59,194 条，其中清标 11,093 条、协议 48,101 条。
- 结构化历史参数：28,117 条。
- 项目—供应商—风机类型案例：965 组。
- 默认可进入数值分析的记录：16,975 条；仅包括已识别供应商、已识别参数、有数值且属于供应商提交值的记录。
- 159 份文件提取状态为 `ok`；7 份 PDF 为部分文本层；28 份 PDF 无文本层。后两类文件仅使用包内已提取且位置明确的内容；包内没有文本证据的部分不进入自动分析。

结构化记录主要覆盖：一次风机、二次风机、引风机、烟气再循环风机、炉墙冷却风机、炉墙冷却引风机、落差墙冷却风机、密封风机及其他风机。

历史供应商主要包括：新乡西玛、宁风科技、山东章鼓、上风高科、鞍山钢峰、佛山迪尔迅、山东临风、河北旺轩、大通宝富、巴法洛、苏州顶裕、金通灵、湖北双剑、陕鼓、安徽安风、湖北三峰等。别名已归一，但每条记录仍保留供应商原文。

## 文件职责

| 文件 | 用途 | 是否可直接形成统计 |
|---|---|---|
| `history-records.jsonl.xz.b64` | 单文件 Base64 文本封装的 XZ 无损结构化参数记录，含项目、供应商、风机类型、招标原文、历史值和单元格位置；由检索工具透明读取，无需手工解码 | 仅 `analysis_eligible=true` 的数值记录可默认参与 |
| `history-cases.jsonl.xz.b64` | 单文件 Base64 文本封装的 XZ 无损案例索引；将记录按项目、供应商和风机类型组成案例，并汇总流量、压力、温度等项目条件 | 用于筛选相近工况 |
| `raw-clear-corpus.jsonl.xz.b64` | 单文件 Base64 文本封装的 XZ 无损清标表逐行原文 | 用于补查未归一参数、结论和上下文 |
| `raw-agreement-corpus.jsonl.xz.b64` | 单文件 Base64 文本封装的 XZ 无损技术协议逐段、逐表、逐页原文 | 用于查条款、部件、供货范围、检验和历史约定 |
| `source-manifest.json` | 全部源文件清单、哈希、项目、文件类型和提取状态 | 不形成统计 |
| `build-summary.json` | 本次构建的数量与覆盖统计 | 不形成技术结论 |

## 证据使用顺序

1. 数值对比先通过检索工具查询 `history-records.jsonl.xz.b64`，确认项目、风机类型、供应商、参数、单位、工况和来源位置。
2. 再到 `raw-clear-corpus.jsonl.xz.b64` 查看同一行及相邻内容，确认是否为投标值、内部核算值、对标列或澄清后值。
3. 涉及材质、结构、供货范围、试验、品牌或责任边界时，检索 `raw-agreement-corpus.jsonl.xz.b64` 补充协议证据。
4. 遇到 `no-text-layer` 或 `partial-text`，只使用包内实际存在且可定位的证据，并在结果中标记证据限制；不得查找外部历史压缩包，也不得把“未提取到”写成“原文件没有”。

## 不丢失信息的处理原则

- 结构化失败不等于删除：未能可靠映射的内容仍保存在两个原文语料文件中。
- 原文值与标准化值并存：输出时优先引用 `historical_value_raw`，数值字段只用于计算。
- 供应商别名与原称并存：内部筛选可用 `supplier_canonical`，证据引用必须能回到 `supplier_raw` 和原文件。
- 内部核算与供应商承诺分开：`value_provenance=internal_calculation` 默认不进入供应商历史统计。
- 旧版、重复版或对标列可能重复同一案例；统计前必须去重，证据引用仍可保留多个版本。

## 强制边界

历史数据只能用于历史变化提示、参考区间、异常筛查和成熟澄清问法。当前项目是否满足要求，只能依据当前招标文件及已批准澄清。任何历史值、历史均值、历史排名或历史评标结论都不得自动变成本次招标门槛。
