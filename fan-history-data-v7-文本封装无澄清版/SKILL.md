# 风机历史数据分析

## 目标

基于康恒既有风机清标表和技术协议，为当前风机技术清标提供可追溯的历史对照。每个历史结论必须能回到具体项目、设备、供应商、原文值、文件和位置。

本 Skill 只做历史参考和异常筛查。当前项目合规性只能依据当前招标文件及已批准澄清；当前技术清标表不生成单独的澄清建议列。

本 Skill 为自包含数据包。日常运行只接收当前项目的招标文件和投标文件，历史库、原文语料、规则及检索脚本均从本 Skill 内部读取；不得要求用户同时提供历史资料压缩包或历史原文件。

历史库的四个数据集各自只有一个文件，并采用导入器兼容的 Base64 文本封装：`references/history-records.jsonl.xz.b64`、`references/history-cases.jsonl.xz.b64`、`references/raw-clear-corpus.jsonl.xz.b64`、`references/raw-agreement-corpus.jsonl.xz.b64`。文件内部仍是 XZ 无损压缩的 JSONL，必须通过 `scripts/query_history.py` 透明读取，不得把 Base64 文本当作历史原文直接引用。

## 何时自动调用

在以下任一情形成立时调用本 Skill：

- 当前采购包、技术规格书或厂家填写文件明确写有一次风机、二次风机、引风机、烟气再循环风机、炉墙冷却风机、炉墙冷却引风机、落差墙冷却风机、密封风机等。
- 文件标题只写“风机”，但参数主体持续出现流量、静压/全压、轴功率、风机效率、叶轮、电机、轴承、机壳、调节门等风机参数。
- 用户要求对风机投标参数比较历史项目、同一供应商历史值、其他供应商区间或历史澄清。

不要因为锅炉、烟气系统或其他设备文件中偶然出现“风机”二字就把整个设备包识别为风机。多设备文件应只对风机章节调用本 Skill。

## 强制边界

1. 当前招标要求是唯一合规基准；历史数据不是门槛。
2. 同一供应商历史项目只用于发现本次参数变化，并必须考虑项目条件不同。
3. 其他供应商历史项目只用于形成参考分布和异常提示，不得直接复制为招标要求。
4. 无招标门槛时只能标记“横向异常待核”或“历史异常待核”，不能判“不满足”。
5. 历史评分、推荐排名、清标结论和材料优劣说法不能自动沿用到新项目。
6. 材质、品牌、结构和传动形式等类别数据不得仅按历史频率或名称自动排序优劣。
7. 供应商提交值与招标方/工艺部核算值必须分开；内部核算值默认不进入供应商历史统计。
8. 缺少可比价格数据时写“价格影响无法判断”，可要求供应商说明是否影响报价。
9. 对外澄清不得披露其他投标人的名称、具体数值、方案、排名或内部评价。
10. 无文本层或部分文本层文件只能标记“包内证据不足，待 OCR/人工确认结果补入历史库”；“未提取到”不等于“原文件未提供”。
11. 历史检索只能读取本 Skill 目录内的 `references/` 和 `scripts/`；不得把外部原始压缩包作为运行依赖。
12. 数据字段 `source_batch` 仅表示历史资料的构建批次，不是文件路径，也不代表需要另行上传或打开任何外部文件。
13. 若包内只有 `no-text-layer` 或不完整证据，该来源不得用于自动结论；写明“包内无可用文本证据，未纳入本次历史分析”，待 OCR 结果补入 Skill 后再使用。

开始分析前阅读 [business-rules.md](references/business-rules.md) 和 [historical-analysis-rules.md](references/historical-analysis-rules.md)。涉及参数归一时阅读 [parameter-dictionary.md](references/parameter-dictionary.md)。

## 标准工作流

### 0. 先验证历史库资产，再声称已完成历史检索

在填写任何“对比历史数据分析”前，先运行：

```powershell
python scripts/query_history.py coverage
```

只有当输出中的 `data_assets.complete=true` 且四个资产均为 `available=true` 时，才可写“已检索到历史项目”或引用历史数值。若任一资产缺失、解码失败或查询命令报错，必须写“历史数据资产不完整，未进行历史数值分析”，不得写“已调用但无可比历史数据”，也不得编造历史样本；当前项目的招标要求、投标要求和差异比较仍可继续完成。

### 1. 建立当前项目对象

从当前招标和投标文件提取：

- 项目、包件、供应商和文件版本。
- 风机类型；复合名称按最长名称识别。
- 参数原名、投标原文、单位和工况。
- 可比条件：设计流量、工况流量、静压/全压、介质、温度、转速、尺寸/重量边界、供货范围。
- 当前参数是否存在招标门槛、缺失、冲突或口径不清。

不要先查历史再反推当前文件含义。

### 2. 检索同一供应商历史

数值参数优先运行：

```powershell
python scripts/query_history.py analyze --fan-type "一次风机" --parameter "轴功率" --value 230 --unit "kW" --supplier "新乡西玛" --condition "TB工况" --design-flow 101400 --static-pressure 5200 --limit 8
```

按实际项目补充 `--working-flow`、`--total-pressure`、`--temperature`、`--speed`。不要填入无法从当前文件确认的条件。

非数值参数或需要查看全部原文时：

```powershell
python scripts/query_history.py records --fan-type "引风机" --parameter "叶轮材质" --supplier "山东章鼓" --condition "TB" --deduplicate --limit 20
```

### 3. 检索其他供应商历史

`analyze` 会同时返回 `same_supplier_history` 和 `other_supplier_history`。若当前供应商未识别，仍可使用其他供应商历史，但必须写明缺少同一供应商历史对照。

优先使用同一风机类型、同一参数、同一单位、同一工况且项目条件相近的记录。相近样本少于 3 条时，工具会退回宽口径样本；必须保留其可比性警告。

### 4. 补查技术协议和未归一参数

涉及结构、材质、品牌、试验、供货范围、质保、服务或责任边界时检索协议原文：

```powershell
python scripts/query_history.py search --corpus agreement --query "轴承冷却方式" --limit 20
```

涉及旧清标表原文、历史澄清或未归一参数时：

```powershell
python scripts/query_history.py search --corpus clear --query "噪声" --fan-type "引风机" --limit 20
```

全文命中只是线索。必须阅读命中内容，确认它是招标要求、供应商承诺、内部核算、评标结论还是协议条款。

### 5. 核验证据质量

查看数据覆盖和需人工复核的文件：

```powershell
python scripts/query_history.py coverage
python scripts/query_history.py sources --project "清远" --limit 20
```

数据结构和字段详见 [data-schema.md](references/data-schema.md)，完整覆盖说明见 [history-overview.md](references/history-overview.md)。

### 6. 形成“对比历史数据分析”

按以下顺序写在一个单元格中：

1. `同一供应商历史项目：`列出最相关项目、设备、原文值、工况、来源和本次变化；说明项目条件差异。
2. `其他供应商历史项目：`列出样本数、项目数、供应商数、历史分布及代表性来源；不把区间写成门槛。
3. `结论边界：`使用“历史变化待核”“历史横向异常待核”“未见统计异常”“样本不足”“无可比历史数据”等，不写合规结论。

示例：

> 同一供应商历史项目：新乡西玛在清远项目一次风机的轴功率（TB工况）原文为“227 kW”（来源：BA2503-2T010-HLB00-清远项目-风机技术清标.xlsx，工作表《清标对比——康恒环境》第8行F列）。本次为“230 kW”；仍需结合两项目流量、压力和温度确认可比性。其他供应商历史项目：同口径去重样本共×条，涉及×个项目、×家供应商，历史中位数为×，统计结果为“×”。该历史分布只用于异常提示，不构成本项目招标门槛。

若无历史证据：

> 未检索到满足同一风机类型、同一参数、同一工况且项目条件可比的历史记录；本项历史对比结论为“无可比历史数据”，仅依据本项目招标与投标原文判断。

### 7. 输出边界

历史数据Skill只返回可追溯的历史项目、历史参数、可比条件、统计结果和异常边界，供“结合历史数据分析”列使用。本技术清标版本不生成“澄清要求”“澄清建议”或其他行动列；如当前投标原文存在缺失或冲突，只保留原文并在历史分析中标记“信息不足”或“口径待核”。

## 数值统计解释

工具使用中位数、四分位数和 IQR 形成统计异常信号：少于 3 条不形成区间，3～4 条只显示历史最小—最大范围，5 条以上可用 1.5×IQR 标记异常。该方法只是内部筛查方法，不是工程标准、公司制度或招标门槛。

任何统计结果都要同时显示：去重样本数、项目数、供应商数、单位、工况、可比性限制和至少一条可追溯证据。

## 失败与降级

- 未识别风机类型：先回到当前文件确认设备；不得用“风机（未细分）”结果替代细分类型结论。
- 未识别供应商：只做其他供应商历史对照，并写“未建立同一供应商历史映射”。
- 单位或工况不一致：不形成混合统计，列案例并标记“口径不可比/待核”。
- 样本不足：列出 1～2 条最相关历史案例，不生成“合理区间”。
- 只有无文本层文件：报告 `source_id` 和文件名，写明“包内无可用文本证据，未纳入本次历史分析”；不得要求当前任务另行查找外部历史压缩包。
- 数据工具与原文冲突：以原文件人工复核结果为准，并记录更正；不要静默改写历史库。

## 数据资产维护

本 Skill 的历史库是只读参考区。只有经技术人员确认了项目、设备、供应商、版本、适用工况和最终承诺后，才可通过独立维护流程新增数据。当前清标运行不得自动把供应商文件写入本库。
